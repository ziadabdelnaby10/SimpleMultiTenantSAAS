# Database Schema

## Overview

The project uses PostgreSQL with Flyway-managed schema evolution.

There are two logical database areas:
- **Shared schema (`public`)** for platform-wide data
- **Tenant schema (`tenant_<companyCode>`)** for tenant-specific business data

## Shared schema

Migration file:
- `src/main/resources/db/migration/common/V1__Init_Common_Tables.sql`

### `tenants`
Stores tenant registration and lifecycle information.

Important columns:
- `id` — primary key
- `created_at`
- `updated_at`
- `deleted`
- `company_name`
- `company_code` — unique
- `email` — unique
- `status` — `PENDING`, `ACTIVE`, `SUSPENDED`, `INACTIVE`
- `admin_full_name`
- `admin_email` — unique
- `admin_username` — unique
- `admin_password`

### `users`
Stores user accounts for the platform.

Important columns:
- `id` — primary key
- `created_at`
- `updated_at`
- `created_by`
- `updated_by`
- `deleted`
- `enabled`
- `username` — unique
- `email` — unique
- `password`
- `first_name`
- `last_name`
- `role`
- `tenant_id` — foreign key to `tenants.id`

A bootstrap platform admin row is inserted during migration.

## Tenant schema

Migration file:
- `src/main/resources/db/migration/tenant/V1__Init_DB_For_Tenant.sql`

Each approved tenant receives a schema named:
- `tenant_<companyCode>`

### `categories`
Tenant-local product categories.

Columns:
- `id` — primary key
- `created_at`
- `created_by`
- `updated_at`
- `updated_by`
- `deleted`
- `name` — unique within the schema
- `description`

### `products`
Tenant-local products.

Columns:
- `id` — primary key
- `created_at`
- `created_by`
- `updated_at`
- `updated_by`
- `deleted`
- `name`
- `reference` — unique
- `description`
- `alert_threshold`
- `price`
- `category_id` — foreign key to `categories.id`

### `stock_mvts`
Tenant-local stock movements.

Columns:
- `id` — primary key
- `created_at`
- `created_by`
- `updated_at`
- `updated_by`
- `deleted`
- `type_mvt` — `IN` or `OUT`
- `quantity`
- `date_mvt`
- `comment`
- `product_id` — foreign key to `products.id`

## Relationship summary

- `users.tenant_id` → `tenants.id`
- `products.category_id` → `categories.id`
- `stock_mvts.product_id` → `products.id`

## Notes

- IDs are stored as `varchar(255)` strings generated by the database.
- Soft delete is used through the `deleted` flag on entities.
- Auditing columns are automatically filled by Spring Data JPA auditing.
